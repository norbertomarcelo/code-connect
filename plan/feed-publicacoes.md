# Feed de publicações (`apps/api` + `apps/web`)

## Contexto

O repo já tem cadastro, login, sessão e rota protegida. O `apps/api` expõe só `users` e `auth`, e `schema.ts` tem uma única tabela. O `apps/web` tem a pilha de auth completa e nenhuma tela de produto — `/inicio` é um `HomePage` placeholder criado na sessão anterior.

O objetivo é entregar as telas do Figma que compartilham a mesma casca (sidebar + coluna de conteúdo): **Feed**, **Detalhe da publicação**, **Publicar**, mais os placeholders **Perfil** e **Sobre nós**; e no backend, o modelo de dados completo (posts, tags, likes, comentários), busca full-text em Postgres e um seed de dados mockados.

### Decisões tomadas com o usuário (fixas)

1. Comentários aninham **exatamente um nível** — resposta de resposta é **422**.
2. **Sem upload de arquivo**: `thumbnail_url` nullable; o campo do form vira "URL da imagem (opcional)".
3. **Material Symbols Outlined** via Google Fonts, `<link>` no `index.html`; o `Icon` atual continua funcionando.
4. **Tags são entidade real** (`tags` + `post_tags`), filtro por interseção (AND), combinado com o FTS.
5. **Anônimo vê tudo**; curtir leva ao `/login` guardando a rota de volta, e o form de comentário vira um convite para entrar.
6. `/perfil` (protegida) e `/sobre` (pública) como placeholders, para o menu não ter link morto.
7. Seed via **`tsx`** (`pnpm api add -D tsx` + script `db:seed`).
8. Sidebar: **"Sair"** autenticado, **"Login"** anônimo. Feed e detalhe **públicos**.

### Divergências deliberadas do Figma

| Figma | Implementação | Motivo |
|---|---|---|
| "Carregar imagem ⬆" + nome do arquivo | Campo de texto "URL da imagem (opcional)" | Decisão 2 — sem storage, sem multipart |
| Avatar fotográfico | `Avatar` com iniciais em círculo de cor determinística | Não existe asset nem coluna no modelo |
| `@julio` | Handle derivado do local-part do email, **no backend** | Não existe `username`; derivar no backend evita expor o email de todo autor num feed público |
| Duas abas, a segunda sem rótulo legível | "Recentes" / "Populares" (`?sort=recent\|popular`) | A segunda aba não tinha rótulo verificável; vira feature real |
| Card inteiro clicável | Thumbnail + título linkam (thumbnail com `aria-hidden` e `tabIndex={-1}`) | Card-inteiro-link quebraria os botões dentro dele |

## Parte 1 — Backend (`apps/api`)

### 1.1 Schema

`drizzle-orm@0.45.2` **não tem nada de full-text search** — sem tipo `tsvector`, sem `to_tsvector`/`ts_rank`/`websearch_to_tsquery`, sem operador `@@`. A saída é `customType` + `generatedAlwaysAs` + `.using('gin', …)` + fragmentos `sql\`\``. Isso foi verificado rodando contra PGlite 0.5.8 (Postgres 18.3), a mesma major do Docker.

```ts
import { sql } from 'drizzle-orm';
import {
  type AnyPgColumn, customType, index, pgTable, primaryKey, text, timestamp, uuid,
} from 'drizzle-orm/pg-core';

/**
 * drizzle-orm 0.45 has no tsvector column type. `customType` only has to emit
 * the right DDL name: the column is generated by Postgres, never written from
 * JS and never selected back.
 */
const tsvector = customType<{ data: string; driverData: string }>({
  dataType() {
    return 'tsvector';
  },
});

export const tags = pgTable('tags', {
  id: uuid('id').primaryKey().defaultRandom(),
  slug: text('slug').notNull().unique(),
  label: text('label').notNull(),
});

export const posts = pgTable(
  'posts',
  {
    id: uuid('id').primaryKey().defaultRandom(),
    authorId: uuid('author_id').notNull()
      .references(() => users.id, { onDelete: 'cascade' }),
    title: text('title').notNull(),
    description: text('description').notNull(),
    body: text('body').notNull(),
    thumbnailUrl: text('thumbnail_url'),
    createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
    // Weighted so ts_rank puts a title hit above a body hit. Column names stay
    // unqualified: Postgres stores this expression verbatim.
    searchVector: tsvector('search_vector').generatedAlwaysAs(
      sql`setweight(to_tsvector('portuguese', coalesce(title, '')), 'A') || setweight(to_tsvector('portuguese', coalesce(description, '')), 'B') || setweight(to_tsvector('portuguese', coalesce(body, '')), 'C')`,
    ),
  },
  (table) => [
    index('posts_search_vector_idx').using('gin', table.searchVector),
    index('posts_created_at_idx').on(table.createdAt.desc()),
  ],
);

export const postTags = pgTable('post_tags', {
  postId: uuid('post_id').notNull().references(() => posts.id, { onDelete: 'cascade' }),
  tagId: uuid('tag_id').notNull().references(() => tags.id, { onDelete: 'cascade' }),
}, (table) => [
  primaryKey({ columns: [table.postId, table.tagId] }),
  index('post_tags_tag_id_idx').on(table.tagId),
]);

export const postLikes = pgTable('post_likes', {
  postId: uuid('post_id').notNull().references(() => posts.id, { onDelete: 'cascade' }),
  userId: uuid('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  // The composite PK is what turns a double like into a 23505, which
  // `isUniqueViolation` already knows how to read.
}, (table) => [primaryKey({ columns: [table.postId, table.userId] })]);

export const comments = pgTable('comments', {
  id: uuid('id').primaryKey().defaultRandom(),
  postId: uuid('post_id').notNull().references(() => posts.id, { onDelete: 'cascade' }),
  authorId: uuid('author_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
  // Nesting is capped at one level in the service, not in the schema: Postgres
  // cannot express "the parent must itself be a root".
  parentId: uuid('parent_id').references((): AnyPgColumn => comments.id, { onDelete: 'cascade' }),
  body: text('body').notNull(),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
}, (table) => [index('comments_post_id_created_at_idx').on(table.postId, table.createdAt)]);
```

A self-FK **exige** a anotação `(): AnyPgColumn =>`, senão o `tsc` acusa referência circular e o build cai. Sem `relations()`: a listagem precisa de subqueries escalares e `ts_rank`, que a API relacional não expressa, e misturar dois estilos de query no mesmo serviço seria pior.

**Conferir à mão no `0001_*.sql` gerado:** a coluna gerada sai como `"tsvector" GENERATED ALWAYS AS (...) STORED`; as duas PKs compostas; os FKs com `ON DELETE cascade`, incluindo a self-FK; `USING gin ("search_vector")`; os `--> statement-breakpoint` (o `migrate()` do PGlite depende deles); e commitar também `meta/_journal.json` e `meta/0001_snapshot.json`.

⚠ **Nunca rodar `drizzle-kit push` nem `studio` neste schema** — o Postgres normaliza a expressão da coluna gerada, então o `push` vai querer recriar a coluna toda vez. O fluxo do repo (`generate` + `migrate`, snapshot contra snapshot) não sofre disso.

### 1.2 `OptionalJwtAuthGuard`

Não existe guard opcional nem `@Public()` no repo. O `AuthGuard` do `@nestjs/passport` sempre retorna `true` em `canActivate`; quem lança o 401 é o `handleRequest` default. Basta sobrescrevê-lo.

```ts
// src/auth/guards/optional-jwt-auth.guard.ts
@Injectable()
export class OptionalJwtAuthGuard extends AuthGuard('jwt') {
  handleRequest<TUser = AuthenticatedUser | undefined>(
    err: unknown, user: unknown, _info: unknown, _context: ExecutionContext,
  ): TUser {
    // A strategy blowing up is a real failure; a failed authentication is not.
    if (err) throw err;
    // passport hands us `false` when the strategy rejected the request.
    return (user || undefined) as TUser;
  }
}
```

`@CurrentUser()` passa a devolver `AuthenticatedUser | undefined`. Isso **não quebra nada**: `createParamDecorator` devolve um `ParameterDecorator` puro, e o tipo de retorno da factory não restringe a anotação do parâmetro — `auth.controller.ts` não muda uma linha. Cada handler anota o que o *seu* guard garante, e o TypeScript não checa essa correspondência: quem garante é o guard. Isso merece um comentário no decorator, porque engana na revisão.

Três módulos novos: `src/posts/`, `src/comments/`, `src/tags/`. `PostsModule` importa `TagsModule`. `DatabaseModule` é `@Global()` e o `PassportModule` já está registrado no `AuthModule`, então nenhum deles precisa importar `AuthModule`.

| Método + rota | Guard | Sucesso | Erros | `Location` |
|---|---|---|---|---|
| `GET /posts?q&tags&sort&page&limit` | Optional | `200` paginado | `422` | — |
| `GET /posts/:id` | Optional | `200` | `400`, `404` | — |
| `POST /posts` | Jwt | `201` | `401`, `422` | `/posts/{id}` |
| `POST /posts/:id/likes` | Jwt | `201` | `400`, `401`, `404`, `409` já curtido | `/posts/{id}/likes` |
| `DELETE /posts/:id/likes` | Jwt | `204` | `400`, `401`, `404` post inexistente | — |
| `GET /posts/:postId/comments` | — | `200` | `400`, `404` | — |
| `POST /posts/:postId/comments` | Jwt | `201` | `400`, `401`, `404`, `422` resposta de resposta | `/comments/{id}` |
| `GET /comments/:id` | — | `200` | `400`, `404` | — |
| `GET /tags` | — | `200` | — | — |

- **`ParseUUIDPipe` em todo param de id.** Sem ele `/posts/abc` vira 500 (`invalid input syntax for type uuid`) em vez de 400. O `ValidationPipe` global mudou só o status do class-validator para 422; o `ParseUUIDPipe` continua em 400, que é o que o CLAUDE.md pede para input malformado.
- **`GET /comments/:id` existe** para o `Location` do comentário não ser link morto — o CLAUDE.md limita aninhamento a um nível e manda expor o filho como recurso top-level.
- **`DELETE` de like é idempotente**: `204` mesmo sem like prévio; `404` só se o post não existe.
- **Nenhum DTO expõe o email do autor.** O handle é derivado no backend (`src/users/handle.ts`), do local-part do email. **Handles não são únicos** — promover para coluna `username` é trabalho futuro.
- O query DTO precisa de `@Type(() => Number)` em `page`/`limit` (com `transform: true`, sem isso chega `'2'` e `@IsInt()` reprova) e de um `@Transform` que quebra `tags` por vírgula. Defaults: `sort='recent'`, `page=1`, `limit=12` (6 linhas de 2 colunas no grid).

**DTOs de resposta** (classes simples, só `@ApiProperty`, `!`): `AuthorResponseDto {id,name,handle}`, `TagResponseDto {slug,label}`, `PostSummaryResponseDto` (+ `thumbnailUrl: string|null`, `tags[]`, `likeCount`, `commentCount`, `viewerHasLiked`), `PostDetailResponseDto extends PostSummary { body }`, `PaginatedPostsResponseDto {items,page,limit,total,totalPages}`, `PostLikeResponseDto`, `CommentResponseDto`, `CommentThreadResponseDto extends Comment { replies }`.

### 1.4 A query de busca — o ponto mais arriscado

Executada contra PGlite com dados semeados: busca só por `q`, só por tags, AND de duas tags, `viewerHasLiked` por usuário, `q`+tags com `total`, e input com aspas e `--`.

```ts
private filter(q: string | undefined, tagSlugs: string[]): SQL | undefined {
  const conditions: SQL[] = [];

  if (q) {
    conditions.push(
      sql`${posts.searchVector} @@ websearch_to_tsquery('portuguese', ${q})`,
    );
  }

  if (tagSlugs.length > 0) {
    // AND-intersection: the post must carry EVERY requested tag. One grouped
    // pass over post_tags instead of N correlated EXISTS subqueries.
    const postsWithEveryTag = this.db
      .select({ postId: postTags.postId })
      .from(postTags)
      .innerJoin(tags, eq(tags.id, postTags.tagId))
      .where(inArray(tags.slug, tagSlugs))
      .groupBy(postTags.postId)
      .having(sql`count(distinct ${tags.slug}) = ${tagSlugs.length}`);

    conditions.push(inArray(posts.id, postsWithEveryTag));
  }

  return conditions.length > 0 ? and(...conditions) : undefined;
}
```

`'portuguese'` é literal, não parâmetro: o primeiro argumento de `websearch_to_tsquery` é um `regconfig` e o Postgres não infere isso de um placeholder de texto. É constante do nosso código, nunca input. **`q` e os slugs são bound** (`$1`, `$2`…), não concatenados.

Contadores como subqueries escalares (juntar `post_likes` e `comments` ao mesmo tempo multiplicaria linhas e forçaria `DISTINCT` sobre toda a projeção):

```ts
const likeCount = sql<number>`(select count(*) from ${postLikes} where ${postLikes.postId} = ${posts.id})`.mapWith(Number);
const commentCount = sql<number>`(select count(*) from ${comments} where ${comments.postId} = ${posts.id})`.mapWith(Number);
const viewerHasLiked = viewerId
  ? sql<boolean>`exists (select 1 from ${postLikes} where ${postLikes.postId} = ${posts.id} and ${postLikes.userId} = ${viewerId})`.mapWith(Boolean)
  : sql<boolean>`false`.mapWith(Boolean);

const orderBy = sort === 'popular'
  ? [desc(likeCount), desc(posts.createdAt)]
  : q ? [desc(rank), desc(posts.createdAt)] : [desc(posts.createdAt)];
```

**N+1 evitado com exatamente 3 queries, independentes do `limit`:** a página, o `count(*)` do total, e todas as tags de todos os posts da página numa só (`inArray(postTags.postId, ids)`, agrupadas em memória — guardar contra lista vazia, que não é SQL válido). Os comentários seguem o mesmo padrão: **uma** query traz raízes e respostas juntas e o agrupamento é em memória.

## Parte 2 — Frontend (`apps/web`)

### 2.1 Tokens — resolvendo o conflito de cores

O feed inverte a relação das telas de auth: lá o body é `#171d1f` e o card é **mais escuro** (`#0d1214`); aqui o fundo é Grafite `#00090e` e os cards são **mais claros** (`#171d1f`).

**Decisão: não tocar em `--color-page`, `--color-surface` nem no `background` do `body`.** `--color-page` já *é* `#171d1f`, exatamente o Cinza Escuro do Figma — então o feed reusa `bg-page` para cards e sidebar, e ganha só um token novo para o fundo da casca. Zero classe alterada nos componentes existentes ⇒ zero pixel e zero teste de auth quebrado.

```css
--color-graphite: #00090e;   /* Grafite - app shell background (feed) */
--font-icon: "Material Symbols Outlined";
/* Figma type scale: Prompt, line-height 1.5 */
--text-paragraph-sm: 0.9375rem;   /* 15px */
--text-paragraph: 1.125rem;       /* 18px */
--text-paragraph-lg: 1.375rem;    /* 22px */
```

Ressalva cosmética aceita: no overscroll aparece o `#171d1f` do body atrás do grafite. A alternativa inverteria o contraste das telas de auth.

### 2.2 Material Symbols e o átomo `Icon`

```html
<link href="https://fonts.googleapis.com/css2?family=Material+Symbols+Outlined:opsz,wght,FILL,GRAD@24,400,0,0&display=block" rel="stylesheet" />
```

Duas escolhas conscientes: **`display=block`, não `swap`** — numa fonte de ícones, `swap` significa mostrar a *palavra* `account_circle` durante o FOUT; `block` deixa o espaço em branco e depois o glifo aparece. E **instância estática `@24,400,0,0`**, que dispensa `font-variation-settings` e portanto não adiciona CSS nenhum além do token.

O `Icon` ganha um segundo ramo. `IconName` vira `SvgIconName | MaterialIconName`, `isSvgIcon` checa o mapa primeiro, e o ramo SVG sai **byte a byte igual** com o default `size='sm'` → `width/height = 20`. `Button` e `TextLink` recebem `icon?: IconName`, que só foi *alargado* — nada quebra, e `Icon.test.tsx` continua passando sem alteração.

```tsx
return (
  <span
    // aria-hidden keeps the ligature text ("account_circle") out of the
    // accessibility tree; translate="no" keeps machine translation from
    // rewriting it and destroying the glyph.
    aria-hidden="true"
    translate="no"
    className={[...]}
  >
    {name}
  </span>
)
```

`login` existe nos dois conjuntos; como `isSvgIcon` checa primeiro, ele fica **fora** de `MaterialIconName` e o JSDoc registra a regra. Em jsdom a fonte nunca carrega, então o texto `"search"` existe no DOM — como está `aria-hidden`, as queries por role/label não são afetadas. **Convenção: nunca consultar ícone por `getByText`.**

### 2.3 Componentes

`Button` **estendido** em vez de novos atoms: `variant` ganha `outline | secondary | ghost` e surge `size: 'sm' | 'md'`. Defaults preservados ⇒ teste atual verde.

**`PostThumbnail` é a solução de placeholder** e cobre os **dois** caminhos: `src` nulo *e* falha de carga.

```tsx
const [failed, setFailed] = useState(false)
```

**`AppShell`** é dono do `<main>`, como o `AuthTemplate` é do dele — cada página renderiza o próprio `<h1>` dentro.

### 2.4 Layout com `<Outlet />` e rotas

**Decisão: rota de layout aninhada**, não um wrapper repetido por página. Com wrapper, o React desmonta e remonta `SidebarNav` a cada transição (elemento de rota diferente), piscando o estado ativo do `NavLink`. Com `<Outlet />`, a sidebar não remonta e a casca é declarada num lugar só. O `AuthProvider` continua **fora** do `RouterProvider`, como hoje.

```tsx
const router = createBrowserRouter([
  { path: '/', element: <Navigate to="/feed" replace /> },
  // Kept so old bookmarks and the previous session's placeholder land somewhere.
  { path: '/inicio', element: <Navigate to="/feed" replace /> },
  { path: '/login', element: <LoginPage /> },
  { path: '/cadastro', element: <SignupPage /> },
  { path: '/recuperar-senha', element: <ForgotPasswordPage /> },
  {
    element: <AppLayout />,   // <AppShell><Outlet /></AppShell>
    children: [
      { path: '/feed', element: <FeedPage /> },
      { path: '/publicacoes/:id', element: <PostPage /> },
      { path: '/sobre', element: <AboutPage /> },
      { path: '/publicar', element: <ProtectedRoute><NewPostPage /></ProtectedRoute> },
      { path: '/perfil', element: <ProtectedRoute><ProfilePage /></ProtectedRoute> },
    ],
  },
])
```

**`src/pages/HomePage/` é apagado inteiro** (4 arquivos). Era um placeholder cuja única função — saudar e oferecer "Sair" — passa para a `SidebarNav`. O default `redirectTo` da `LoginPage` muda de `/inicio` para `/feed`.

### 2.5 Transporte e busca de dados

Três módulos novos em `src/lib/api/` (`posts.ts`, `comments.ts`, `tags.ts`) no padrão existente: export nomeado `async`, `const { data } = await apiClient…`, **sem try/catch**, JSDoc de uma linha com verbo/rota/status. Tipos em `types.ts`.

`errors.ts` ganha **`'not-found'`** na union e o ramo `if (status === 404)` — hoje um post inexistente cai em `'unknown'` e mostra mensagem genérica. `src/auth/messages.ts` usa `switch` com `default` e cadeias de `if`, então alargar a union é seguro.

**Pasta nova `src/hooks/`** com `useAsyncData` e `useDebouncedValue`. Vale um hook em vez de repetir o `useEffect` do `AuthProvider`: são 3 consumidores, o feed refaz o fetch a cada mudança de filtro **com debounce de 300 ms** (respostas fora de ordem são cenário real, não hipotético), e a flag de cancelamento copiada 4 vezes é exatamente o que sai errado em uma das cópias. `useAsyncData` usa um **contador de request**, não um booleano, para descartar resposta atrasada, e expõe `setData` para o like otimista sem refetch. TanStack Query foi rejeitado: seria a maior dependência do `apps/web` para 5 endpoints.

`src/posts/messages.ts` espelha `src/auth/messages.ts` para a copy pt-BR.

### 2.6 Páginas

**`q`, `tags`, `sort` e `page` vivem na query string** — feed filtrado vira link compartilhável, o botão voltar funciona, F5 preserva o filtro, e a página passa a ser função pura da URL sem duplicar estado. Busca escreve na URL com `replace` (uma busca não deixa 12 entradas no histórico); chips e abas escrevem com **push** (ação deliberada merece histórico). Qualquer mudança de filtro faz `delete('page')`.

`status` do `useAuth()` entra nas deps do fetch de propósito: o bootstrap resolve depois do primeiro render, e `viewerHasLiked` só fica correto quando o token vai junto.

Like otimista: aplica o delta na hora, chama a API, e **reverte no catch**. Anônimo vai para `/login` com `state: { from: location }` — a mesma forma que o `ProtectedRoute` usa, então a `LoginPage` já sabe devolver.

`PostPage` usa dois `useAsyncData` (post e comentários); anônimo vê um convite de login no lugar do `CommentForm` (o `TextLink` já estende `ComponentProps<typeof Link>`, então aceita `state` sem mudança no atom). Comentário novo entra via `setData`, sem refetch. `ProfilePage` e `AboutPage` são mínimas e **sem `<main>` próprio** — o `AppShell` é dono dele.

**Limitação aceita:** o campo de busca é semeado da URL só na montagem, então voltar no histórico para um `q` diferente atualiza a lista mas não o texto do campo. Sincronizar nos dois sentidos com debounce no meio é a receita clássica de loop.

## Riscos conhecidos

**Bloqueantes se ignorados**
- `TRUNCATE users` quebra assim que existe FK — 4 specs falham; migration e correção têm que ir no mesmo commit.
- A self-FK exige `(): AnyPgColumn =>`, senão o build cai.
- Sem `ParseUUIDPipe`, id malformado vira 500.

**Decisões que vale reconfirmar depois**
- A segunda aba do Figma não tinha rótulo verificável; virou "Populares". O `sort` já é o ponto de extensão.
- Handles derivados do email **não são únicos** — dois `julio@` de domínios diferentes colidem.
- `Location` do like aponta para a coleção, não para o item (o item seria dois níveis, proibido pelo CLAUDE.md).

**Operacionais**
- `drizzle-kit push`/`studio` querem recriar `search_vector` sempre; usar só `generate` + `migrate`.
- Token expirado + guard opcional = 200 anônimo, não 401; o `AuthProvider` só descobre no `/auth/me`.
- `@CurrentUser()` não é checado pelo TypeScript — anotar errado compila e explode em runtime.
- `ts_rank` sem normalização por tamanho: texto longo rankeia alto por repetição. Com 8 posts não dá para calibrar.
- O stemming `'portuguese'` é agressivo: "acessível" acha "acessibilidade" (bom), "a" não acha nada (confunde).
- `useAsyncData` usa deps explícitas e o oxlint do web não tem `exhaustive-deps` — dep esquecida não é pega por lint nem por tipo.
- URLs de imagem externas no seed dependem de rede; uma é quebrada de propósito, as outras podem quebrar sozinhas.
- Mensagens 422 do class-validator seguem em inglês, mapeadas por prefixo de campo — mudar nome de propriedade no DTO quebra o mapeamento em silêncio.
- `App.tsx` continua sem teste, agora carregando também o `AppLayout`.
